# Move the AI-SDLC mode to hoshin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The AI-SDLC mode drives the hoshin plugin instead of ai-sdlc, migrates an ai-sdlc workspace on request, and shows each task's observed-red verdict and stored test output on the build page.

**Architecture:** hoshin's program is ai-sdlc 1.4.0 renamed plus `red`, `migrate` and `schedule`. Part 1 is a rename across `kata-sdlc`, `kata-core` tests, `app/src-tauri` and the frontend, done so every commit stays green. Part 2 adds two program calls (`red show`, `migrate`) behind the existing `Program` gateway, decides the verdict and the migration offer in Rust, and shows them in Angular.

**Tech Stack:** Rust (kata-sdlc, kata-core, Tauri backend), ts-rs bindings, Angular 22 + SpartanNG, Node.js 22.18 program (hoshin `tools/hoshin.ts`).

**Spec:** GitHub issue satish-krishna/kata#85 (as rewritten 2026-11-15), hoshin `tools/CLIENTS.md` (the contract, after hoshin#22), hoshin `tools/GRAMMAR.md` sections "Observed red" and "Migrating from ai-sdlc".

## Global Constraints

- hoshin's plugin floor is `1.0.0`; there is no other version gate. Node.js floor stays `22.18`.
- The plugin is found in the catalog by name `hoshin`, providing `skill:build`. The run-spec's required plugin is `hoshin`.
- The mode's display name `AI-SDLC` stays. Lowercase `ai-sdlc` is gone from code, UI, tests, `CLAUDE.md` and current docs, except: the legacy marker name `.ai-sdlc.json` in the migration code and its UI, and `docs/superpowers/` and `docs/prds/` (history).
- Test fixtures whose master repository was named `ai-sdlc` name it `hub`.
- The program is called only through `Program` in `crates/kata-sdlc/src/hoshin.rs` (today `ai_sdlc.rs`). Kata reads nothing under `<git dir>/hoshin/` itself; the stored output comes from `red show` only.
- Every decision is computed in Rust and reaches Angular as data (`.claude/skills/kata-architecture/SKILL.md`). Angular formats.
- Never hand-edit `app/src/bindings/`. Regenerate with `cargo test -p kata-core --features ts export_bindings`, `cargo test -p kata-sdlc --features ts export_bindings`, `cargo test -p kata-app --features ts export_bindings`.
- Child processes only through `kata_core::proc` (`hidden_command`, `run_limited`); Kata starts `node`, never `git` or `gh`.
- Gates per commit: `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, the tests of the crates touched. `cargo test --workspace` needs `node app/scripts/stage-sidecar.mjs` first. Frontend: `npm run lint`, `npx stylelint "src/**/*.css"`, `npm test -- --watch=false` from `app/`.
- CSS only against custom properties; read `app/CLAUDE.md` and the `app:house-style` skill before any template or stylesheet.
- US English. Markdown without hard wraps.
- The build run's leash (`runspec.rs`, 7200 s per repository) is not changed: `red record` takes at most 600 s per task inside it, and the engineer can raise the form's timeout. Record this in the `runspec.rs` doc comment of the default.

## Review Focus

1. A workspace saved in the Workbench before the switch (only `.ai-sdlc.json`) is opened: the home page offers the migration instead of an opaque "no master repository" error. Test in Task 9.
2. Migrate is asked for while a run or a build hold is live in that workspace: it is refused with a sentence naming why, and nothing is moved. Test in Task 9.
3. A change built under ai-sdlc (plan tasks without `test`, entries without `red`) is opened: no verdicts, no error, no "no test" noise on every row. Test in Task 6.
4. A `not observed` task whose ledger record is on another machine: the output panel says "no record on this machine" instead of failing the page. Test in Tasks 7 and 8.
5. A hand-edited `red` value that is not a verdict, and stored output with ANSI color codes: shown as text, ANSI stripped, no crash. Tests in Tasks 6 and 7.
